LA GUÍA

Tu mesa, de principio a fin.

Una mesa de control manual para entrenamiento y exhibición de Taekwondo. Un PC, un operador y una pantalla externa en el mismo navegador.

De la configuración
a la segunda pantalla.

  1. Prepara la sesión. Introduce el evento, los competidores, 1 o 3 rondas y una duración de 1, 2 o 3 minutos. Guardar abre el control.
  2. Abre la pantalla externa. Permite la ventana emergente, muévela al segundo monitor y activa Pantalla completa. Debe usar el mismo navegador y perfil que el control. Para presentar en este monitor, usa Marcador a pantalla completa desde Control. Al salir vuelves al control; también puedes abrir Marcador y activar Pantalla completa desde allí.
  3. Dirige el combate. Inicia o pausa el reloj. Registra de +1 a +6 puntos por decisión manual. Gam-jeom suma una penalización al atleta y un punto al rival. −1 corrige un punto del atleta seleccionado, sin bajar de cero ni cambiar al rival. «KO · Gana por KO» declara ganador a ese atleta tras confirmar, detiene el reloj y cierra el combate. Deshacer permite corregir un KO marcado por error y deja el reloj pausado.
  4. Continúa o corrige. Siguiente ronda conserva los puntos acumulados. Deshacer revierte la última acción disponible y pausa el reloj sin devolver el tiempo transcurrido. Al agotarse la última ronda, Control y Marcador muestran al ganador por puntos acumulados o un empate. Las correcciones posteriores actualizan ese resultado.
  5. Guarda y respalda. Abre Gestión del combate para guardar un resumen, intercambiar lados o preparar un combate nuevo. Exporta JSON desde Preparar combate para conservar una copia externa. Nuevo combate archiva el actual antes de reiniciar.

Hecho para
entrenar y exhibir.

La alpha ofrece puntuación manual, reloj, rondas, penalizaciones, resultado final por puntos acumulados, deshacer, resúmenes, respaldo JSON y una pantalla externa de solo lectura.

El operador decide qué acción puntuar y confirma manualmente un KO cuando corresponda. El combate termina por KO o al agotarse la última ronda configurada. Los valores +1 a +6 son incrementos manuales: no asignan automáticamente una técnica ni representan una edición de un reglamento.

No incluye sensores, homologación WT, victorias por asalto, desempates, gestión de torneos, cuentas ni conexiones entre dispositivos. Compartir el enlace en otro equipo abre una sesión independiente.

La pestaña de control debe permanecer abierta. Al recargarla el reloj queda pausado. Usa la segunda ventana en la misma sesión del navegador; una ventana privada o un perfil distinto no comparte los datos.

El navegador guarda.
Tú conservas la copia.

Free conserva el combate, las últimas 120 acciones y hasta 10 resúmenes nuevos en el almacenamiento local del sitio. Las acciones más antiguas se retiran al llegar a 120. Los resúmenes no se borran automáticamente: al llenarse el historial, exporta JSON y elimina los que elijas antes de guardar otro.

El respaldo sigue siendo JSON con los datos del combate, sin informe PDF ni CSV. Las copias nuevas usan el formato v5 para conservar el ganador por KO; requieren esta versión o una posterior para restaurarse. También se admiten las copias v4. Las copias anteriores válidas conservan sus tiempos, rondas, impactos y hasta 80 resúmenes. Al preparar un combate nuevo se utilizan los presets de Free; restaurar una copia no recorta los registros anteriores.

Exporta JSON antes de borrar datos del navegador, cambiar de dominio o trasladarte a otro equipo. Importar JSON valida el archivo y pide confirmar antes de reemplazar los datos actuales. Solo acepta el formato de esta alpha y archivos de hasta 5 MB.

Cada dirección guarda sus propios datos. Si cambias de dirección, exporta primero tu copia JSON desde la que utilizabas e impórtala después en la nueva. Mantén Control y Marcador en la misma dirección para que compartan el combate.

¿Utilizabas la dirección anterior? Ábrela para exportar tu copia JSON antes de trasladar el combate a esta dirección.

Los datos del prototipo v2/v3 se recuperan cuando son válidos: se conservan el combate y los resúmenes compatibles. El deshacer y los registros detallados del formato anterior no se migran; las claves antiguas se mantienen en el navegador.

La aplicación no incorpora cuentas, analítica ni envío de los combates a un servidor. Vercel recibe las solicitudes necesarias para servir la demo. Cualquier persona con acceso a tu perfil del navegador puede ver los datos locales.

La alpha 0.1 publicada funciona en un navegador y todavía no utiliza React, Go ni una base de datos. El diseño objetivo siguiente amplía Octajang a torneos; sus funciones aún requieren implementación y pruebas.

Diseño definido · Implementación pendiente

El producto al que evolucionará Octajang tendrá varias áreas, jueces y pantallas conectados a la red local. Podrá operar sin Internet: los jueces propondrán puntos y la mesa de cada área los confirmará.

  1. JuecesEnvían propuestas del combate asignado.
  2. Mesa del áreaConfirma o rechaza cada propuesta.
  3. Servidor del recintoValida, guarda y publica el estado oficial.
  4. PantallasMuestran el resultado confirmado.
React + TypeScript + ViteInterfaz por roles, componentes compartidos y rutas con React Router.
CSS con tokens + CSS ModulesDiseño consistente, componentes accesibles y estilos acotados.
GoUn servidor local para la interfaz, la API, los permisos y el reloj oficial.
SQLiteArchivo transaccional del evento en la PC del servidor. Los clientes acceden por la API.
HTTPS + WebSocketContratos, revisiones, confirmaciones y recuperación de conexión por área.
Pruebas y operaciónConcurrencia, duplicados, revocación, respaldo, restauración y pruebas físicas.

Vercel seguirá alojando la demo pública. El servidor local servirá todos los recursos del torneo, con sesiones y permisos propios; el archivo SQLite nunca se compartirá por una carpeta de red.

El primer presupuesto técnico de validación será de cuatro áreas y 21 sesiones. Es una hipótesis para medir, no una capacidad ya demostrada. Sensores, reglamentos automáticos y distribución local corresponden a fases posteriores.

Estado del proyecto

  1. Alpha 0.1 · Publicada. Marcador de entrenamiento, control desde un PC y pantalla externa. Mantener esta demo mientras evoluciona el producto.
  2. Frontend React · Planificado. Migrar vistas y componentes, conservar los respaldos y comprobar los flujos y la accesibilidad.
  3. Servidor y un área LAN · Planificados. Go, SQLite, contratos, sesiones y flujo de propuestas confirmadas por la mesa. Probar desconexiones y restauración.
  4. Varias áreas · Planificadas. Aislar combates, asignaciones y colas. Medir la carga y operar con dispositivos físicos en el recinto.
  5. Beta de torneo · Pendiente. Acordar la edición del reglamento, probar decisiones y resultados, y documentar una sesión completa.
  6. Sensores · Después. Investigar protocolo y calibración con hardware real antes de anunciar integración PSS.
